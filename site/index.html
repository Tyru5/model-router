Run one coding task through several agents.

Model Router is a terminal app and CLI. Each stage runs on the agent and model you pick, Codex, Claude Code, Amp, Cursor, or your own CLI, and hands a structured result to the next. The run ends with a brief of what changed and how it was checked.

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/Tyru5/model-router/releases/latest/download/model-router-installer.sh | sh

Then run mr in a repository. Linux and macOS, MIT licensed, source on GitHub.

Pick the agent and model for each stage

A workflow is a list of stages. Each runs one harness with one model, unattended in the background or in the harness's own terminal. A blank model uses the harness's default.

  • Five workflow presets. Quick task, Bug fix, Full feature, Investigation, and Best-of-3 implement.
  • Structured handoffs. A summary, verdict, findings, decisions, files, and tests, instead of raw output.
  • Router checks. Commands the router runs itself after a stage, with no shell.

Implementation opens the harness's own terminal

Work with Claude Code as you normally would. When it exits, the run stops at a checkpoint: accept the handoff, retry, or swap the model.

Ctrl+B detaches. Quit mr and the session keeps running; the next mr reconnects to it.

A second opinion, more hands, or the best of three

Reviews can send the work back. A stage can ask other agents for help. An implement stage can run on several harnesses at once and keep the best result.

What it won't do without asking

Model Router starts other agents with your own logins. It doesn't store their keys, loosen their permissions, or commit to your repository unless you tell it to.

No commits by default

Only an enabled ship stage commits, on a new branch, after you confirm a preview and a secret scan passes.

No stored credentials

Provider keys come from environment variables at launch and are redacted in records.

Native permissions

Each harness keeps its own approval rules unless a stage overrides them.

Trust before commands

A repository's config can't run checks, custom adapters, or delegates until you run model-router trust.

No silent model swaps

A failed stage stops and offers retry, a replacement model, or resume.

Clean exits

A stage's harness process group ends with the stage. Bubblewrap or sandbox-exec can wrap any stage.

Works with the agents you already use

Install and log in to each harness yourself. model-router doctor checks what it finds without sending a request.

# run unattended in an isolated worktree
model-router run --task-file spec.md --unattended --worktree

# retry a stage with another model
model-router resume RUN_ID --retry --model opus

# read the brief and the diff
model-router report RUN_ID --diff

# what a stage received, and what was cut
model-router handoffs RUN_ID --stage review

# commit on a new branch and open a draft PR
model-router ship RUN_ID --draft-pr

# let other agents start runs
model-router serve --mcp

Release notes

Every release lists its changes in the changelog.

  1. 0.3.128 November 2026

    Security: repository-local Git hooks, filters, merge drivers, and diff tools can no longer run from router or TUI Git commands. Ship plans name any repository Git config a push would follow.

  2. 0.3.024 November 2026

    A first-launch tour. Delegation: a stage's agent hands tasks to other harnesses and models. Schedules an agent can propose and you approve.

  3. 0.2.121 November 2026

    An install script with SHA-256 verification. Hardening for serve --http and config reads.

  4. 0.2.020 November 2026

    init --detect adapts presets to the harnesses you have installed. Stall timeouts for unattended stages.

  5. 0.1.04 October 2026

    First release: the TUI, stages unattended or interactive, presets, task imports, and themes.
