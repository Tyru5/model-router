Route each stage of a task to the agent that does it best.

Model Router sends one task through Codex, Claude Code, Gemini, Amp, or your own CLI, with the model you choose for every stage. It ends with a brief: what changed, how it was checked, and what to read closely.

curl -fsSL https://model-router.tiru5.me/install.sh | sh

Then run mr in a repository. Linux and macOS.

Unattended when it can be
Research, review, and the closing brief run in the background with their own timeouts. You're notified when a run needs you.

        
Interactive when it matters
Implementation opens the harness's own terminal. Detach with Ctrl+B, quit mr, and come back to the same screen.

        
Handoffs, not scrollback
Each stage passes a structured summary, verdict, findings, and test evidence to the next.

      

    

  


  

    

      

        
Let a stage hand work to other agents

        
Turn on delegation for a stage and its agent can pass self-contained tasks to other harnesses and models in the middle of a run. The router launches every task, so it owns the process, the sandbox, and the spend. The agent only asks.

        
    
          
  • Read-only or in a worktree
    A shared task reads the parent's checkout and can't write to it. A worktree task works on a copy and returns a patch the parent applies with task_apply.
    • 
          
  • Never above the parent
    Each task runs unattended in its own OS sandbox and can't get more write access, native permissions, or network than the stage that started it.
    • 
          
  • Woken, not polling
    When its tasks finish, the router starts a follow-up turn of the parent with their results.
    • 
          
  • Schedules wait for you
    An agent can propose a recurring run. It fires only after you approve it with model-router schedules approve.
    • 
        

        
Claude Code, Codex, OpenCode, and custom adapters can delegate, including from interactive stages. Any harness can take a task. Delegates in a repo's config need model-router trust.

      

      

        
# .model-router.toml
[delegates.codex-review]
harness = "codex"
model = "gpt-6.2-sol"
effort = "high"

[delegates.claude-impl]
harness = "claude"
model = "claude-opus-5-5"
isolation = "worktree"

[[workflows.stages]]
id = "implement"
harness = "claude"
[workflows.stages.delegation]
delegates = ["codex-review", "claude-impl"]
max_parallel = 3

Interlocks you can't pull past

      
The router coordinates agents. It doesn't take their keys, widen their permissions, or touch your Git history without asking. Each one stays locked until you take an explicit step to release it.

      

        
No commits by default
Only a ship stage commits, on a new branch, after you confirm a preview.

        
Your logins stay yours
No stored credentials. Provider keys are read from your environment at launch and redacted in every record.

        
Native permissions
Each harness keeps its own approval rules unless a stage explicitly overrides them.

        
Trust before commands
A repo's config can't run checks, custom adapters, or delegates until you run model-router trust.

        
No silent model swaps
A failed stage stops and offers retry, a replacement model, or resume.

        
Clean exits
Every harness process group ends with its stage. An optional bubblewrap or sandbox-exec sandbox per stage keeps Git config and hooks read-only.

# try the whole flow offline, no model calls
cargo run -- --config examples/demo.toml

# see exact commands, nothing launched
model-router preview --task 'Respect Retry-After'

# run it unattended in an isolated worktree
model-router run --task-file spec.md --unattended --worktree

# retry a stage with a different model
model-router resume r-0418 --retry --model opus

# read the brief and the diff
model-router report r-0418 --diff

# approve a schedule an agent proposed
model-router schedules approve s1

# let other agents drive it
model-router serve --mcp
